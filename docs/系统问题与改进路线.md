# EduTrack 系统问题与改进路线

> 文档用途：作为 EduTrack 学生课程项目的整改计划，指导项目从当前演示原型逐步完善为可以部署到网站、供老师在线演示的版本。
>
> 当前目标：先保证演示稳定、数据可信、权限基本安全，再逐步完成数据库和生产部署。

## 一、项目现状

EduTrack 是一个高中考试成绩管理与分析系统，包含三个角色：

- 学生：查看个人成绩、成绩趋势和学习目标。
- 教师：查看班级成绩、成绩分布、学生进退步情况。
- 管理员：查看班级、教师、考试和学校数据。

当前版本已经具备：

- React + TypeScript 前端。
- Express + TypeScript 后端。
- JWT 登录认证。
- 学生、教师、管理员三类页面。
- 本地 JSON 成绩数据。
- 班级成绩统计和趋势图表。

当前数据规模约为：

- 3 个年级。
- 15 个班级。
- 1327 名学生。
- 15 名教师。
- 75 份成绩报告文件。

前端和后端目前都可以成功构建，但仍属于课程项目原型，暂时不适合直接承载真实学校数据。

## 二、总体推进原则

我们会按照下面的顺序推进：

1. 先修复会导致演示失败或数据错误的问题。
2. 再修复权限和密码问题，避免出现明显安全漏洞。
3. 然后统一数据结构和业务逻辑。
4. 再迁移到 MongoDB，解决长期存储和部署问题。
5. 最后部署网站并进行完整演示测试。

每完成一个阶段，都要进行一次可见的验收，而不是一次性改很多内容。

## 三、优先级说明

| 优先级 | 含义 | 处理原则 |
|---|---|---|
| P0 | 必须优先解决 | 不解决就可能无法安全演示或出现明显错误 |
| P1 | 重要问题 | 影响系统可信度、可维护性或老师验收 |
| P2 | 后续完善 | 不影响第一版演示，但影响完整性和长期使用 |
| P3 | 优化项目 | 在核心功能稳定后再处理 |

## 五、详细问题与解决办法

### P0-1：接口存在越权访问风险

**问题表现**

后端接口目前大多只检查用户是否登录，没有充分检查用户是否有权访问指定的班级或学生。例如，学生理论上可能通过修改 URL 中的学号，访问其他学生的成绩。

**影响**

- 学生隐私可能泄露。
- 教师可能查看不属于自己的班级。
- 这是上线前必须修复的安全问题。

**解决办法**

在后端增加统一的资源权限检查：

- 学生只能访问自己的学生 ID。
- 教师只能访问自己负责的班级。
- 管理员可以访问全校数据。
- 所有权限判断放在后端，不能只依赖前端菜单隐藏。

建议增加类似下面的权限函数：

```text
canViewStudent(user, studentId)
canViewClass(user, classId)
```

并在学生详情、学生成绩、班级详情、班级成绩、班级分析等接口中统一调用。

**验收标准**

- 学生登录后访问自己的成绩成功。
- 学生访问其他学生成绩返回 403。
- 教师访问自己班级成功。
- 教师访问其他班级返回 403。
- 管理员访问所有班级成功。

### P0-2：密码和 JWT 密钥不安全

**问题表现**

- 管理员账号密码直接写在源码中。
- 学生允许使用统一的 `123456`。
- 教师密码明文保存在 JSON 文件中。
- JWT 未配置时使用默认密钥。

**影响**

任何拿到源码的人都可以获得登录凭据；部署后也容易被伪造 Token。

**解决办法**

第一步，先完成演示环境的最低安全要求：

- 将管理员账号、密码和 JWT 密钥放入环境变量。
- 如果没有设置 JWT 密钥，后端直接禁止启动。
- 删除代码和页面中的真实演示密码提示。
- 教师和学生密码不再以明文返回接口。

第二步，迁移数据库后：

- 使用 bcrypt 保存密码哈希。
- 登录时使用 bcrypt 比较密码。
- 首次登录强制修改密码。
- 连续登录失败后临时锁定账号。
- 增加登录日志。

**验收标准**

- 源码中不再出现管理员真实密码。
- 数据接口不会返回密码。
- JWT 密钥缺失时服务启动失败。
- 修改密码后旧密码不能登录。

### P0-3：教师成绩分布图使用硬编码数据

**问题表现**

教师首页的成绩分布图使用固定数组，而不是接口返回的数据。因此图表可能与页面上显示的班级和考试不一致。

**解决办法**

- 后端统一计算成绩区间和人数。
- 前端调用 `/data/classes/:classId/distribution`。
- 前端只负责展示接口返回的数据。
- 成绩区间应根据考试满分和业务规则配置，而不是随意固定。
- 学科平均分图应使用得分率，或者根据每个科目的满分进行归一化。

**验收标准**

- 切换考试后图表数据同步变化。
- 图表人数总和等于参考人数。
- 删除或修改一条成绩后重新加载页面，图表会变化。
- 图表中的学科满分规则正确。

### P0-4：数据导入页面是假功能

**问题表现**

点击“重新加载”或导入按钮后，页面只是等待 1.5 秒，然后显示导入成功，并没有真正上传、解析或保存文件。

**解决办法**

第一版演示可以分成两个选择：

**方案 A：短期演示方案**

- 将页面改名为“本地数据状态”。
- 删除“导入成功”提示。
- 改为显示当前已加载的文件数量、班级数量和学生数量。
- 明确说明“当前版本使用项目内置 JSON 数据”。

**方案 B：完整导入方案**

- 后端使用 `multer` 接收文件。
- 使用 `xlsx` 解析 Excel/CSV。
- 校验必需字段、学号、班级、科目、分数和满分。
- 导入前生成预览结果。
- 导入成功后刷新缓存或写入数据库。
- 返回成功数量、失败数量和错误明细。

课程项目第一版建议先完成方案 A，再实现方案 B。

**验收标准**

- 页面中的按钮不会假装完成没有执行的操作。
- 页面显示的数量与真实数据一致。
- 上传非法文件时显示明确错误。
- 正常文件导入后，成绩查询页面可以看到新数据。

### P0-5：前端数据说明已经过时

**问题表现**

导入页面显示的班级数、学生数和成绩文件数与当前真实数据不一致。

**解决办法**

- 删除硬编码说明。
- 后端增加数据概览接口。
- 前端根据接口动态显示数量。
- 所有文件统计统一从后端获取。

**验收标准**

页面显示的班级数、学生数、教师数和成绩文件数与后端统计完全一致。

### P1-1：修改密码接口没有真正修改密码

**问题表现**

接口无论旧密码是否正确，都会返回“密码修改成功（演示模式）”。

**解决办法**

- 根据用户角色读取用户记录。
- 校验旧密码。
- 校验新密码长度和复杂度。
- 使用 bcrypt 保存新密码。
- 修改成功后撤销旧 Token，要求重新登录。

**验收标准**

- 旧密码错误时修改失败。
- 新密码过弱时修改失败。
- 修改成功后旧密码不能登录。
- 新密码可以登录。

### P1-2：数据依赖本机绝对路径

**问题表现**

数据加载代码中写死了本机目录：

```text
C:\Users\mimo\Desktop\Edu
```

部署到服务器或其他电脑后会失效。

**解决办法**

使用项目根目录和环境变量：

- 使用 `process.cwd()` 或基于当前源文件计算路径。
- 使用 `DATA_DIR` 环境变量指定数据目录。
- 部署时将数据目录作为配置项传入。
- 不把个人电脑路径写入代码。

**验收标准**

- 项目复制到另一个目录仍能启动。
- 在 Linux 服务器上能读取数据。
- 修改数据目录环境变量后，服务能读取新目录。

### P1-3：数据库代码存在但业务没有真正使用

**问题表现**

项目包含 MongoDB 连接和模型文件，但实际登录、成绩查询和班级分析仍然读取 JSON 文件。

**解决办法**

MongoDB 迁移分为几个小步骤：

1. 先确认本地 MongoDB Atlas 账号和数据库连接字符串可以使用。
2. 添加 `.env` 文件，连接字符串只放在环境变量中。
3. 创建数据导入脚本，把 JSON 数据导入 MongoDB。
4. 对比导入前后班级数、学生数、教师数和成绩数量。
5. 先迁移读取接口。
6. 再迁移登录和写入接口。
7. 最后删除对 JSON 的业务依赖。

建议的数据集合：

- `users`
- `students`
- `teachers`
- `classes`
- `exams`
- `scores`
- `announcements`

**验收标准**

- 重启服务后数据仍然存在。
- 不依赖本地 JSON 也能登录和查询成绩。
- MongoDB 中的记录数量与原始 JSON 一致。
- 数据库连接失败时，页面显示明确错误，而不是伪装成正常。

### P1-4：考试类型和分析规则写死

**问题表现**

考试类型固定为“月考1、月考2、月考3、期中考试、期末考试”，无法支持新学期、新考试或其他考试名称。

**解决办法**

建立考试实体，至少包含：

```text
id
name
type
term
date
gradeId
subjectFullScores
status
```

成绩记录通过 `examId` 关联考试，而不是只依赖考试名称。

**验收标准**

- 管理员可以新增一个考试。
- 不同学期可以有同名考试。
- 不同年级可以设置不同满分。
- 学生和教师页面能看到新建考试。

### P1-5：管理员页面部分功能只有查看

**问题表现**

“班级管理”“教师管理”“考试管理”目前主要是查询和展示，不能真正新增、修改或删除。

**解决办法**

先明确课程项目的展示范围：

- 如果只需要展示分析能力，将菜单改成“班级浏览”“教师信息”“考试成绩”。
- 如果需要体现管理能力，则增加 CRUD API 和表单。

建议实现顺序：

1. 考试新增和编辑。
2. 学生信息编辑。
3. 教师账号重置密码。
4. 班级和教师绑定。
5. 删除操作增加二次确认和操作记录。

**验收标准**

- 页面名称与实际能力一致。
- 不能操作的按钮不再显示。
- 每个新增、修改和删除操作都有明确成功或失败提示。

### P1-6：缺少统一输入校验和错误处理

**问题表现**

接口参数主要靠手动判断，错误返回格式也不完全统一。

**解决办法**

- 使用 Zod 或 Joi 定义请求参数。
- 统一返回格式：

```json
{
  "success": false,
  "error": {
    "code": "INVALID_INPUT",
    "message": "请求参数不正确",
    "details": []
  }
}
```

- 对学生 ID、班级 ID、考试 ID、分数范围统一校验。
- 前端统一处理 401、403、404、500。

**验收标准**

- 非法参数不会导致服务器异常。
- 前端能够显示用户能理解的错误提示。
- 所有接口错误格式一致。

### P2-1：查询效率不高，无法分页

**问题表现**

查询学生或班级成绩时，会遍历多个成绩文件。数据量增加后会变慢，也无法分页。

**解决办法**

- 迁移到 MongoDB 后增加索引。
- 为学生 ID、班级 ID、考试 ID 建立索引。
- 成绩列表增加 `page` 和 `limit`。
- 班级分析可以增加缓存或预计算。

**验收标准**

- 查询 1000 条以上成绩时页面仍能正常加载。
- 成绩列表支持分页。
- 接口返回总数和当前页信息。

### P2-2：缺少操作日志和备份机制

**问题表现**

目前无法追踪谁导入了成绩、谁修改了数据，也没有正式的数据备份恢复流程。

**解决办法**

- 增加 `audit_logs` 集合或日志表。
- 记录操作人、操作类型、目标数据、时间和结果。
- 导入前自动备份。
- 提供管理员下载备份和恢复备份功能。
- 生产环境使用数据库定期备份。

**验收标准**

- 修改成绩后可以查到操作人和时间。
- 导入失败不会破坏原有数据。
- 可以恢复到导入前状态。

### P2-3：缺少自动化测试

**解决办法**

逐步增加测试，不要求一次完成：

- 登录成功和失败测试。
- 学生越权访问测试。
- 教师跨班级访问测试。
- 成绩计算测试。
- 成绩导入校验测试。
- 前端核心页面的端到端测试。

**验收标准**

每次修改核心逻辑后，至少可以自动验证登录、权限和成绩查询。

### P3-1：前端生产包较大

**问题表现**

前端构建包较大，包含 ECharts 等较重依赖。

**解决办法**

- 使用路由懒加载。
- 按页面拆分管理员、教师和学生模块。
- 配置 Vite 分包。
- 只在需要图表的页面加载 ECharts。

**验收标准**

- 首页不需要等待全部业务页面加载。
- 首屏加载时间明显下降。
- 图表页面仍能正常运行。

### P3-2：移动端和无障碍体验需要完善

**解决办法**

- 检查手机宽度下的表格和弹窗。
- 为图标按钮增加文字提示。
- 增加键盘操作和焦点样式。
- 对重要图表提供文字摘要。

这部分不影响第一版老师演示，可以放在核心功能完成后处理。

## 六、建议的实际推进阶段

### 第一阶段：保证演示可信和基本安全

目标：老师打开网站后，看到的数据是真实的，页面不会展示明显假功能。

任务：

1. 修复学生和教师越权访问。
2. 移除硬编码图表数据。
3. 修复导入页面的假成功提示。
4. 修正所有过时的数据统计。
5. 处理 JWT 密钥和演示账号配置。
6. 增加接口错误提示。

完成标志：

- 三种角色可以正常登录。
- 学生只能看自己的成绩。
- 教师只能看自己的班级。
- 教师图表和后端数据一致。
- 所有页面显示数量一致。

### 第二阶段：完善业务模型和可维护性

目标：系统功能名称与实际能力一致，代码不依赖个人电脑。

任务：

1. 删除本机绝对路径。
2. 完成真实修改密码。
3. 增加统一请求校验。
4. 设计考试实体。
5. 明确管理员页面是“管理”还是“浏览”。
6. 增加基础接口测试。

完成标志：

- 项目复制到其他目录可以运行。
- 主要业务接口有参数校验。
- 页面不再承诺尚未实现的功能。

### 第三阶段：MongoDB 迁移

目标：数据不再依赖项目文件，能够支持网站部署。

任务：

1. 重新创建或检查 MongoDB Atlas 项目。
2. 配置数据库用户和网络访问权限。
3. 配置本地 `.env` 文件。
4. 编写 JSON 到 MongoDB 的导入脚本。
5. 校验导入数量。
6. 改造后端查询接口。
7. 改造登录接口。
8. 测试数据库断开和重连情况。

完成标志：

- 网站部署后不需要读取个人电脑文件。
- 重启服务器不会丢失数据。
- 登录、成绩查询和统计都从数据库读取。

### 第四阶段：网站部署和老师演示

目标：老师可以通过一个网址访问系统。

任务：

1. 前端构建并部署到 Vercel 或其他静态托管平台。
2. 后端部署到 Render、Railway、Vercel Serverless 或其他服务。
3. MongoDB Atlas 作为数据库。
4. 配置前端 API 地址。
5. 配置 CORS。
6. 配置生产环境 JWT 密钥。
7. 准备演示账号。
8. 进行登录、查询、图表和权限测试。

完成标志：

- 老师通过网址可以打开首页。
- 学生、教师、管理员账号都能登录。
- 主要页面数据正常加载。
- 网站重启或重新部署后数据仍然存在。

## 七、老师演示建议

建议演示流程控制在 5 到 8 分钟：

1. 打开系统首页，说明三个用户角色。
2. 使用学生账号登录，展示成绩总览和趋势图。
3. 切换教师账号，展示班级平均分、成绩分布和进退步学生。
4. 切换管理员账号，展示学校数据概览和考试查询。
5. 简单展示权限控制，例如学生不能查看其他学生数据。
6. 最后说明系统使用的技术栈和后续 MongoDB 部署方案。

演示账号应使用专门的测试数据，不要使用真实学生隐私数据。

## 八、MongoDB 推进说明

MongoDB 不需要一开始就全部完成。建议采用“先让本地版本稳定，再一步迁移”的方式。

下一步开始时，需要准备：

- MongoDB Atlas 账号。
- 一个新的数据库项目。
- 数据库连接字符串。
- 允许本机访问的网络配置。

连接字符串只能放在本地 `.env` 和部署平台的环境变量中，不能提交到 Git。

## 九、当前建议

现在不建议直接开始 MongoDB 迁移。更稳妥的顺序是：

1. 先完成第一阶段的 P0 问题。
2. 运行一次完整本地演示。
3. 确认业务规则和页面显示没有明显错误。
4. 再开始 MongoDB 配置和数据迁移。

这样可以避免在数据库连接尚未稳定时，同时排查页面、权限和数据问题。

## 十、下一阶段研究与开发规划

在完成第一阶段 P0 问题并稳定现有演示版本后，结合导师评价和项目实际情况，下一阶段按以下顺序推进：

### 1. 在线考试功能

开发在线考试模块，支持教师在线出卷、学生在线答题和系统自动批改。第一版优先实现选择题、判断题等客观题的自动评分；后续增加填空题、简答题和作文题，其中主观题由教师人工评分。考试成绩需要自动纳入现有成绩分析体系，形成“考试—批改—分析”闭环。

### 2. 知识点掌握情况分析

建立题目与知识点的关联关系，生成班级知识点掌握情况和学生个人知识点掌握情况。第一版实现班级知识点统计和学生个人雷达图，后续再增加个性化学习建议。

### 3. 智能问答功能

在成绩、考试和知识点数据结构稳定后接入大语言模型，实现基于业务数据的多角色问答。学生只能查询本人数据，教师只能查询负责班级，管理员才可以查询全校数据。

### 4. 在线论坛功能

开发按班级和科目分区的论坛，支持发帖、回复、点赞和匿名显示。匿名只对前台展示，后台仍保留真实用户信息，并逐步增加删除、举报和审核机制。

### 推荐实施顺序

```text
P0-5
→ P1-4 考试模型
→ P1-6 输入校验
→ 在线考试第一版
→ 知识点分析第一版
→ 智能问答
→ 在线论坛
→ MongoDB 迁移和部署完善
```

下一阶段优先形成“教师出卷—学生答题—自动评分—成绩分析—知识点薄弱分析”的完整演示链路。论坛可以相对独立开发，大模型接入应在底层数据结构稳定后进行。
